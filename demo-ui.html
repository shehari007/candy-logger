1Live playground

Every button below writes to a real Candy Logger panel. Drag it, resize it, pin rows, search, switch themes — it's the actual published build, loaded from ./dist/.

📊 Log levels

Six levels, each color-coded and independently filterable, with live counts in the toolbar.

🏷️ Tags & custom actions

Attach colored tags at the call site, or add one inline with the 🏷️ button on any row. Custom actions get the whole entry.

🧨 Things that used to crash it

v2.0 threw a TypeError out of console.log on a circular object. These all render safely now — that's the headline fix.

Try it: open devtools and confirm the native console still receives the real, fully-inspectable objects — the panel never replaces them with copies.

🛡️ Injection safety

A logger's whole job is displaying untrusted data. These payloads all render as text — object keys, tag labels and action labels included.

If any of these were still vulnerable, you'd see an alert(). You won't — every cell is built with textContent, never innerHTML.

📦 JSON viewer

Objects collapse to a preview and expand into syntax-highlighted JSON with a copy button. Keys and strings are actually highlighted now.

💅 Console format specifiers

%s %d %i %f %o %c are applied the way browsers do — so framework banners read correctly instead of leaking raw CSS.

⚡ Throughput & retention

Sticky-bottom scrolling: scroll up to read and the panel stops yanking you down, showing a “N new” pill instead.

Pinned rows are exempt from maxLogs. Pin a row with 📌, then fire a burst — it survives, and it comes back after a reload.

🔌 Headless capture & sinks

The store is the source of truth, so getLogs() works with no panel at all — and you can pipe entries anywhere.

2Configure the panel

Change anything and the panel is rebuilt with your options. Every option here does something — v2.0 shipped four that were silently ignored.

destroy() removes the panel, every listener it added and its stylesheet — nothing leaks across hot reloads. v2.0 had no way to tear the panel down at all.

3Usage

Three lines to get going. The panel is a lazy dynamic import, so bundlers drop it entirely from builds that never enable it.

Capture console.*

// idempotent — StrictMode & HMR safe
import { overrideConsole } from 'candy-logger';

const logger = overrideConsole({
  enabled: import.meta.env.DEV,
});

console.log('Hello', { user: 1 });

Use it directly

import { createLogger } from 'candy-logger';

const log = createLogger({ enabled: true });

log.success('Build passed');
log.error(new Error('boom'));   // full stack
log.getLogs();                     // works headless

Ship logs anywhere

// the panel is just one sink
const off = log.addSink({
  write(entry) {
    if (entry.level === 'error') {
      fetch('/api/logs', {
        method: 'POST',
        body: JSON.stringify(entry),
      });
    }
  },
});

No build step

<!-- one self-contained file -->
<script src="https://unpkg.com/candy-logger@2">
</script>
<script>
  overrideConsole({ enabled: true });
</script>

5Feature set

📊 Table view

Time, level, tags, message and per-row actions in a sortable, filterable table.

🔍 Model-backed search

Debounced search over the log data itself, so collapsed payloads still match.

📌 Pins that persist

Pinned rows stay on top, survive clear(), ignore maxLogs, and come back after reload.

🌗 Real themes

Dark, light, or auto following prefers-color-scheme and updating live.

♿ Accessible

Named buttons, aria-pressed toggles, a polite live region, focus rings, reduced-motion support.

📱 Mobile-ready

Full-screen sheet under 640px and pointer-event dragging that works on touch.

🔌 Sinks

Pipe entries to a server, Sentry, or a test spy. The panel is just one consumer.

💾 Export

Download the buffer as JSON, or copy every line to the clipboard in one click.

🪶 Zero deps

No runtime dependencies. ~6 kB gzipped core; the panel loads only when enabled.
